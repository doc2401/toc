# 关于本地镜像站的搭建

> 本文分享如何搭建一个个人/局域网内通用的离线开发文档镜像站。

---

## 💡 为什么需要本地镜像站？
- **极致的加载速度**：本地静态服务（如 Nginx、http-server）响应耗时通常小于 5ms，大段代码和 API 文档瞬间加载。
- **无网环境支持**：在没有互联网的内网/封闭机房开发时，随时可供查阅。
- **防止版本下线**：官方经常只保留最新几个 LTS 的文档，本地镜像可完整归档所有老旧及小众版本。

---

## 🛠️ 核心搭建流程

### 1. 文档源文件采集
- **官方离线下载**：多数大厂（如 Oracle JDK、Spring、Eclipse）均提供 HTML 离线文档的 `.zip` 或 `.tar.gz` 压缩包。
- **整站镜像工具**：如果官方不提供离线包，可以使用命令行工具 `wget` 或图形界面工具 `HTTrack` 对在线文档站进行整站爬取。
  ```bash
  wget --mirror --convert-links --adjust-extension --page-requisites --no-parent https://example.com/docs/
  ```

### 2. 平级文件夹结构设计
为了统一文档索引的管理，我们将导航索引站 `toc` 目录与各个文档的主目录放置在平级关系下。
```text
codeDoc/
  ├── jdk.25/               # JDK 25 离线解压目录
  ├── spring.7.0.1/         # Spring 离线解压目录
  └── toc/                  # 我们的 Docsify 文档导航站
        ├── index.html
        ├── java/
        └── spring/
```

### 3. Docsify 相对路由跳转
由于 `toc` 与离线文档是平级目录：
- 默认在 `toc` 二级子目录（如 `/java/jdk.md`）中，使用 `../../jdk.25/` 就可以完美指向父级外的目标文件夹。
- 这样，不论是在线上部署（保持平级目录），还是在本地随意移动 `codeDoc` 主目录，所有链接永远不会失效。
